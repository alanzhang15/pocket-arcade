# Pocket Arcade

Alan's personal offline web arcade: small, polished, battery-friendly games that run on Steam Deck (Chrome kiosk tiles),
iPhone/iPad (home-screen web app), and laptops. Hosted on GitHub Pages from this repo (public):
https://alanzhang15.github.io/pocket-arcade/ — saves sync to the private repo `alanzhang15/arcade-saves`.

For a new game use the `new-arcade-game` skill; for a remake of an older (e.g. Flash-era) game use `port-arcade-game`.

## Layout
- `js/core.js` — the shell: menu, input, audio, saves/scores, sync hook, pause/game-over, offline. Games never edit it.
- `js/sync.js` — GitHub save sync. `css/arcade.css` — shell styles. `fonts/` — bundled Silkscreen + Chakra Petch.
- `games/<id>/game.js` — one file per game, calls `Arcade.register({...})`. The folder name must equal the id.
- `games/<id>/art/{cover,wide,hero,logo}.png` — Steam library art, generated by `node tools/render-art.mjs <id>`.
- `games/order.txt` (optional) — menu order, one id per line.
- `tools/build.py` — injects script tags into index.html, writes games.json, refreshes sw.js. Run after any change.
- `tools/test-game.mjs` — headless play test + performance budget. `deck/arcade-tiles.py` — Steam Deck tile installer.
- Reference games: `games/cave-flyer` (real-time, one button) and `games/switchboard` (turn-based, pointer, onDemand, autosave).

## The game contract
```js
Arcade.register({
  id: 'kebab-id', title: 'Title', blurb: 'One line for the menu card',
  controls: 'Shown on the pause screen. Mention touch AND controller.',
  orientation: 'any' | 'landscape',
  pointer: false,          // true = point-and-click game: taps/mouse/trackpad are the pointer; the stick drives a virtual cursor
  redraw: 'always',        // 'onDemand' = draw only when update() returns true, input happens, or api.requestDraw()
  fps: 60,                 // 30 for slow games: halves update+draw work
  pixelated: false,        // true = render 360 rows and upscale (pixel art; ~1/4 the fill cost on Deck)
  thumb(ctx, w, h) {},     // 112x84 menu card art
  art(ctx, w, h, kind) {}, // Steam art scene, kind = cover|wide|hero (no text; the tool adds the title)
  create(api) { return { update(dt) {}, draw(ctx, view) {}, resize(view) {}, getState() {} }; }
});
```
api: `view {w, h=360, scale}` · `input.held/pressed .up .down .left .right .a .b .x .y .l .r .start .select` ·
`input.stick/stick2 {x,y}` (-1..1) · `pointer {x, y, down, pressed, released, active, virtual}` (world units) ·
`sfx.tone({f,to,d,type,v})`, `sfx.noise({d,v})` · `save(obj, slot?)` / `load(slot?)` (slot 'main' default; 'run' is the
autosave slot) · `best()` · `player()` · `requestDraw()` · `gameOver(score)`.

The shell owns: pause (Start/Esc/button, auto on backgrounding), game-over panel + top-10 scores per player,
restart/quit, autosave (calls `getState()` on pause, quit, backgrounding and every 30 s; cleared on game over),
cloud sync, menus, and drawing the virtual cursor. Start and Select are reserved for the shell in menus.

## Rules for every game
**Self-contained and offline.** One `game.js`, no libraries, no network, no external URLs, no `localStorage`
(use `api.save/load` so sync works), no `setTimeout/setInterval` (use `dt`). Sounds come from `api.sfx`; art is drawn
in code (canvas paths, small sprites built at startup). Keep a file under ~60 KB (exception: `sol-tycoon`, a deep
tycoon where performance matters more than size).

**Plays everywhere.** Every action must work with (1) touch, (2) a controller alone, (3) keyboard. World is 360 units
tall; width varies (~500 on phone portrait to ~830 on Deck/landscape phones): lay out from `view.w` in `resize()`.
Touch targets at least 40 units. Keep HUD in the top-left (pause button is top-right). Controller mapping
conventions: A = primary/confirm, B = back/undo/secondary, X/Y = extra actions, L/R = cycle tools/pages,
d-pad = discrete moves or a cell highlight, left stick = movement or the virtual cursor (R held = fast cursor).
For pointer games also give d-pad + A a way to do everything (a highlighted cell/item), because the virtual cursor
is slow for frequent clicks.

**Battery budget** (Steam Deck is the target; `node tools/test-game.mjs` enforces the first two):
- update+draw p95 < 4 ms, average < 2 ms on the test machine.
- Turn-based / puzzle / management games use `redraw: 'onDemand'` and return `true` from `update()` only while
  something visibly changes (animations included). Slow real-time games use `fps: 30`.
- No allocation in hot loops: no new arrays/objects/closures/template strings per frame; reuse pools; cache text.
- Build gradients, glows (`shadowBlur`) and complex shapes once into offscreen canvases in `create()`/`resize()`;
  never `shadowBlur`, `filter`, or `createLinearGradient` inside `draw()`.
- Draw only what's on screen; avoid full-screen alpha layers; prefer `fillRect` over paths for rectangles.
- Pixel-art games set `pixelated: true`.

**Saves.** Long-term progress (unlocked levels, settings) → `api.save(obj)`. Mid-run state → implement `getState()`
returning a small plain object (< 50 KB), and resume from `api.load('run')` at the top of `create()`. Scores come only
from `api.gameOver(score)`; games that don't end (sandbox) can call it from a "finish" action.

**Look.** Match the arcade: dark navy grounds (#0d1124 / #070a17), amber #ffb547, cyan #5ce1e6, rose #ff5d8f,
text #e9ecff, muted #8d95c4; Silkscreen for HUD numbers/labels, Chakra Petch for sentences. Each game may add one or
two accent colours of its own. Show a short "how to play" state before the first input.

**Originality (the repo and site are public).** Remakes keep the mechanics and feel but use original names, art,
text, sounds and level layouts. Never copy assets, code, logos or names from the original into this repo.

## Definition of done (every new or changed game)
1. `python3 tools/build.py` (the edit hook also runs it) and `node --check games/<id>/game.js`.
2. `node tools/test-game.mjs <id>` passes; look at the screenshots in `test-output/<id>/` (Deck, iPhone, game over).
3. `node tools/render-art.mjs <id>`, then `python3 tools/build.py` again, and look at `games/<id>/art/cover.png`.
4. Commit (`<id>: what changed`) and push to main. GitHub Pages publishes in about a minute; installed copies show
   "Update". On the Deck, double-click **Update Arcade Tiles** on the desktop to add the new tile.
5. Tell Alan: what was built, controls on Deck and phone, test numbers (ms, CPU), and anything not yet verified.
